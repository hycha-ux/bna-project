## 0. 한 줄 결론

설계 자체는 촘촘합니다. **빈 곳은 "무엇을 더 만들까"가 아니라 ①재료(참조 사진) ②이겼는지 판정하는 자(측정 도구·기준값) ③숫자끼리의 앞뒤(목표 vs 코드)** 세 군데에 몰려 있습니다.
MediaPipe는 **필수**, InsightFace도 **필수지만 순서는 두 번째**입니다. 둘 다 이 PC에서 설치 장벽이 없다는 것까지 실제로 확인했습니다(아래 2장).

## 1. 빈 곳 — 우선순위 순

### A. 지금 안 정하면 나중에 되돌리기 어려운 것

**A-1. 참조 사진 라이브러리가 텅 비어 있습니다.**
`samples/reference/clinical|selfie/` 에 파일 0장, `config/samples_index.yaml` 의 `refs: []`.
그런데 `docs/gap-review.md` 는 A1(참조 이미지)을 "없으면 목표 미달"로 분류해 뒀습니다. 즉 **가장 중요한 재료가 계획에만 있고 조달 방법이 없습니다.** 문서 어디에도 "누가 · 어디서 · 몇 장 · 상업 이용 권리 확인은 누가"가 없습니다.
쉽게 말하면, 요리법은 다 썼는데 장을 안 봤습니다.
→ 필요한 결정: 모드별 20~30장, 출처(직접 촬영 / 라이선스 스톡 / 자사 보유), 권리 확인 담당자.

**A-2. 성공 기준 1번을 잴 자가 없습니다.**
"블라인드 실사 구분율 60% 이하"가 이 프로젝트의 합격선인데, 이걸 잴 도구(gap-review 의 B4)는 미반영이고 **판정 규칙 자체가 미정**입니다 — 몇 장을, 몇 명에게, 한 사람이 몇 번 보나, 실제 사진과 몇 대 몇으로 섞나.
표본이 작으면 그 숫자는 실력이 아니라 운입니다. 예: 30장 × 5명 = 150판정이면 오차가 ±8%p 수준이라 "58%"와 "66%"를 구분하지 못합니다.
→ 필요한 결정: 표본 수·평가자 수·1인당 판정 수. (도구는 제가 만들 수 있습니다. 키 없이 가능)

**A-3. 결과물에 출처 표식이 없습니다.**
지금은 "전부 오픈"이라 제한 로직이 없는 게 맞습니다. 다만 **파일 자체엔 아무 표시가 없습니다.** `meta.json` 은 우리 폴더에만 남고 JPEG 안에는 안 들어갑니다. 이미지 한 장이 카톡·슬랙·광고 소재로 밖에 나가는 순간, 나중에 "이건 어느 배치의 생성물인가"를 되돌려 찾을 방법이 사라집니다. **이 손실만 소급 복구가 안 됩니다.**
→ 제안(비용 0): 저장할 때 EXIF/XMP 에 배치 ID·프롬프트 버전만 조용히 심어둡니다. 눈에 보이는 표기·워터마크는 법무 가이드 온 뒤에 결정해도 늦지 않습니다.

### B. 목표 숫자와 코드가 서로 안 맞는 곳

**B-1. "통과작 50장" 주문이 실제로는 "시도 50건"입니다.**
브리프는 배치 단위를 "(시술, 모드, **목표 통과 수**)"로 정의했는데, `batch.py` 는 조합 50개를 만들고 각각 최대 3회 재시도할 뿐 **모자란 만큼 새 조합을 보충 생성하지 않습니다.** 통과율 60%면 50장 주문에 30장이 나옵니다.
→ 한 줄 수정으로 해결됩니다(목표치를 채울 때까지 추가 조합 투입).

**B-2. "시간당 통과작 100장"은 현재 설정으로 불가능합니다.**
`batch.py` 의 동시 실행 수 = `min(생성기, 편집기)` = 지금 값으로 **4**. 이미지 1장에 15초만 잡아도 통과작 100장 = 호출 300~500회 = **동시 15~30개**가 필요합니다.
→ 매체별 분당 호출 한도(레이트리밋)를 확인하기 전까지 이 목표 숫자는 근거가 없습니다. 키 수령 후 첫 실측 대상.

**B-3. 비용 상한·월 물량 목표가 없습니다.**
단가표(`pricing.yaml`) 기준으로 계산하면 **통과작 1장 ≈ $0.17(약 240원), 100장 ≈ $17(약 2.4만원)** 입니다(제미나이 기준, 통과율 50% 가정).
→ "월 몇 장"이 정해져야 예산이 서고, "1장당 얼마까지 허용"이 있어야 모델 선택이 데이터로 결정됩니다.

### C. 조용히 틀어지는 자리 (코드 — 오류가 안 나서 더 위험)

**C-1. Before 에 "시술 전 상태"가 없습니다. (가장 큰 구멍)**
`treatments.yaml` 에는 After 변화(`after_change`)만 있고, Before 프롬프트(`config/prompts/before.md`)에는 *팔자주름이 뚜렷하다 · 모공이 크다 · 볼이 붉다* 같은 문장이 한 줄도 안 들어갑니다.
결과: 깨끗한 얼굴이 Before 로 나오면 **After 에 보여줄 변화가 없습니다.** 검수의 `effect_visible` 항목에서 계속 떨어지고, 그만큼 재생성 비용이 나갑니다.
→ 제안: `treatments.yaml` 에 `before_condition` 한 줄씩 추가(시술별 문제 상태 + 경증/중등도 강도 축).

**C-2. 필러만 부위 마스크가 없습니다.**
`filler` 의 `mask_region: custom` 인데 `qa/landmarks.py` 의 폴리곤 목록에 `custom` 이 없습니다. `batch.py` 는 목록에 없으면 마스크 없이 그냥 진행합니다 → **다른 시술은 픽셀이 보존되는데 필러만 조용히 보존이 안 됩니다.** 오류도 경고도 안 납니다.

**C-2b. `requirements.txt` 대로 설치하면 랜드마크 코드가 지금 당장 깨집니다. (실측)**
`qa/landmarks.py` 는 `mp.solutions.face_mesh.FaceMesh` 를 쓰는데, 이건 MediaPipe 의 **옛 방식**입니다. 오늘 실제로 설치해 보니 최신판(**1.0.1**)에는 그 기능이 **아예 없어졌습니다**(`module 'mediapipe' has no attribute 'solutions'`).
게다가 코드는 "미설치면 건너뛴다"만 대비해 놨기 때문에, **설치하면 오류로 멈추고 / 설치 안 하면 조용히 검사를 통째로 건너뜁니다.** 둘 다 목표(축 ②)가 사라지는 길입니다.
**"옛 버전으로 고정하면 되지 않나"도 안 됩니다** — 0.10.35 로 내려서도 확인했는데 거기에도 `solutions` 가 없습니다(설치 가능한 목록 전체가 새 방식만 제공).
→ **유일한 길: 새 방식(Tasks API)으로 옮기기.** 오늘 실제로 돌려서 동작을 확인했습니다 — 모델 파일 `face_landmarker.task` 3.76MB 를 한 번 받아두면 되고, **점 번호 체계(468/478)는 그대로**라 지금 만들어 둔 부위 폴리곤 좌표는 버리지 않아도 됩니다. 고칠 곳은 `qa/landmarks.py` 의 `detect()` 함수 하나(약 10줄)입니다.
※ InsightFace 는 최신판(1.0.1)에서 `from insightface.app import FaceAnalysis` 그대로 동작합니다(실측 확인).

**C-3. 동일인 기준값 하나(0.60)를 두 모드에 같이 씁니다.**
셀카 After 는 장면·헤어가 일부러 바뀌므로 같은 사람이어도 점수가 낮게 나옵니다. 임상(픽셀 보존)과 같은 잣대를 쓰면 셀카가 통째로 떨어질 수 있습니다.
→ 모드별로 기준을 갈라야 하고, 그 값을 정할 **실제 사진 쌍(같은 사람 / 다른 사람) 데이터가 아직 없습니다.** 0.60·0.75 는 지금 임의값입니다.

**C-4. 닮은 얼굴 방어에 틈이 있습니다.**
동일인 기준 0.60 < 중복 기준 0.75. 즉 **서로 다른 사람인데 0.60~0.75 만큼 닮은 조합은 중복으로 안 걸립니다.** "같은 얼굴 반복"이 대량생산의 대표 실패 모드인데 그 구간이 비어 있습니다.

**C-5. 임상 정렬 오차 지표가 자기충족(항상 합격)이 됩니다.**
마스크 밖을 Before 원본 픽셀로 되돌린 뒤(`composite_outside_mask`) 그 이미지로 눈 위치를 재면 오차는 당연히 0에 가깝습니다. 성공 기준 3번("눈 중심 2% 이내")이 자동 충족돼 **지표로서 의미가 사라집니다.**
→ 정렬 검사는 합성 **전** 원본 After 에 대해 재고, 합성본은 따로 기록해야 진짜 모델 성능이 보입니다.

**C-6. 회귀 테스트가 0개입니다.**
마스크 폴리곤 번호(468점 인덱스)는 문서에도 "초안, 시각 확인 필요"라고 적혀 있습니다. 번호가 틀려도 프로그램은 오류 없이 **엉뚱한 곳을 편집**합니다. 눈으로 확인하는 도구부터 필요합니다(키 없이 가능).

**C-7. A/B 실험과 재현이 아직 안 됩니다.**
`Batch(ab_prompt=...)` 자리는 있는데 쓰는 코드가 없고, 생성 시 seed 를 모델에 넘기지 않아 **같은 조건을 두 번 재현할 수 없습니다.** A6 피드백 루프의 전제가 빠져 있습니다.

### D. 사람이 결정·조달해야 하는 것

- **D-1. API 키 3종(GPT·Gemini·Higgsfield) 미수령 → 0단계 스파이크가 통째로 멈춰 있습니다. 일정 리스크 1위.**
- **D-2. 시술 지시문 의료진 검토자 미지정** (문서엔 "추후 지정"). 과장 표현은 광고 심의 리스크로 바로 연결됩니다.
- **D-3. 시술별 나이 가중치가 없습니다.** 가중치가 전역 하나라 *10대 후반 리프팅*, *20대 초반 팔자주름* 같은 비현실 조합이 정상적으로 만들어집니다 → 그 자체가 "AI 같다"의 원인이 됩니다.
- (참고) 브리프 9장은 "시술 8종", 요구사항 목록은 7줄(홍조·모공을 나누면 8)로 표기가 갈립니다.

## 2. MediaPipe · InsightFace — 꼭 필요한가

### 쉬운 설명

| 도구 | 한 줄로 | 비유 |
|---|---|---|
| **MediaPipe** | 사진에서 눈·코·입 위치를 점 468개로 찍어주는 **무료 자(ruler)** | 얼굴 위에 모눈종이를 덮는 것 |
| **InsightFace** | 얼굴을 숫자 512개로 요약해 "같은 사람인가"를 점수로 재는 **무료 신분증 대조기** | 지문 대조 |

둘 다 **내 컴퓨터에서 도는 무료 프로그램**입니다. 호출당 돈이 붙지 않고(0원), 한 장에 0.1초 수준입니다. 그림을 **만드는** 도구가 아니라 나온 그림을 **검사하는** 도구입니다.

### 판정

| 도구 | 어디에 쓰나 | 빼면 어떻게 되나 | 판정 |
|---|---|---|---|
| **MediaPipe** | ① 시술 부위만 편집하는 마스크(A4) ② 임상 정렬 오차 측정(A5) ③ 시술 부위가 화면 안에 있는지 | 축 ②(임상 동일 조건)가 "프롬프트로 부탁하기"로 되돌아갑니다. 성공 기준 3번(눈 중심 2% 이내)은 **측정 자체가 불가능**해집니다 | **필수 · 1단계** |
| **InsightFace** | ① 같은 사람인지 하드 게이트(A3) ② 얼굴 중복 제거(배치 간, B5) | 동일인 판정을 비전 LLM 에 맡기게 되는데, LLM 은 "닮았으면 같다"고 넘어가는 편이고 한 쌍마다 돈이 붙습니다. 무엇보다 **수백~수천 장을 서로 비교하는 중복 제거는 LLM 으로 불가능**합니다(1만 쌍 비교 = 1만 번 호출) | **필수 · 2단계** |

**"AI(비전 LLM)한테 시키면 안 되나요?"** — 두 가지가 다릅니다.
- *정렬 오차 1.7%* 같은 **숫자**는 LLM이 못 냅니다. 눈대중이라 매번 다르게 답합니다.
- *같은 사람인가*는 LLM도 답하지만 관대하고, 한 쌍당 비용이 붙습니다. 로컬 도구는 0원·0.1초·항상 같은 답입니다.
→ 그래서 **LLM = 미적 판단(손·피부·AI티), 로컬 도구 = 수치 판단(위치·동일성·중복)** 으로 나누는 지금 설계가 맞습니다.

**대체재는 있지만 지금 선택이 무난합니다.** MediaPipe 대신 dlib·face-alignment, InsightFace 대신 DeepFace·facenet 이 있습니다. 정확도는 비슷하고 설치는 더 번거롭습니다. 나중에 갈아끼울 수 있도록 **호출부를 한 곳(`qa/landmarks.py`, `qa/identity.py`)에 모아둔 지금 구조를 유지**하면 됩니다.

### 실측 (이 PC, Windows · Python 3.12)

- 두 패키지 모두 **미리 만들어진 설치 파일(wheel)이 있어 컴파일러 설치 같은 장벽이 없습니다.** (`mediapipe 1.0.1` win_amd64 · `insightface 1.0.1` 순수 파이썬 · `onnxruntime 1.29.0`) — 예전에 InsightFace 가 윈도우에서 설치가 까다롭다는 이야기가 있었는데, 지금 버전은 그 문제가 없습니다.
- 내려받는 양: 세 개 합쳐 약 35MB. **InsightFace 는 첫 실행 때 얼굴 인식 모델(buffalo_l) 약 300MB 를 1회 추가로 내려받습니다** — 사무실 PC 기준 문제 없지만, 무인 배치에서 처음 도는 순간 몇 분 멈출 수 있으니 미리 한 번 돌려두는 게 좋습니다.
- ⚠ **다만 최신 MediaPipe(1.0.1)에는 지금 코드가 쓰는 옛 기능이 없습니다 → C-2b 참고. 버전 고정이 필요합니다.**

### 주의 3가지

1. **마스크 폴리곤 번호는 반드시 눈으로 한 번 확인**해야 합니다(현재 초안). 틀려도 오류가 안 납니다.
2. **0.60 / 0.75 기준값은 임의값**입니다. 실제 사진 쌍으로 보정하기 전엔 "동일인 게이트"가 아니라 "그냥 문턱"입니다.
3. 두 도구는 **검수 전용**입니다. 리얼리티(축 ①) 자체를 올려주지는 않습니다 — 그건 참조 사진(A-1)과 후처리의 몫입니다.

## 3. 제안 순서 — 키가 오기 전에 할 수 있는 것

| 순서 | 할 일 | 누가 | 키 필요 |
|---|---|---|---|
