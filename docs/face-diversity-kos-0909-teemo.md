# 얼굴이 비슷해 보이는 이유 + KOS 사진을 베이스로 쓸 수 있나 (티모, 2026-09-09)

요청(성연서님): "연령이나 인종 같은 걸 선택했을 때 비슷한 얼굴이 출력되는 걸 볼 수 있는데,
KOS에서 고객 사진을 베이스로 활용해서 다양한 인물의 사진으로 베리에이션 칠 수 있는지 확인해줘"

> **이번에 KOS를 부른 횟수: 0회. 사진은 한 장도 내려받지 않았습니다.**
> 잰 것은 **우리가 이미 만들어 둔 생성물 21장**이고, 고친 것은 우리 코드입니다.

## 0. 세 줄 요약

1. 얼굴이 실제로 겹치지는 않았습니다 — 153쌍 중 "같은 사람" 판정 **0건**(문턱 0.60, 최대 0.421).
2. 그런데 **인물 명단이 통째로 반복되고 있었습니다.** 러너 기본 seed 가 `5` 로 고정이라
   같은 시술을 두 번 돌리면 **같은 사람 8명**을 다시 그렸습니다. 이게 "비슷하다"의 1순위 원인이고,
   **돈도 키도 안 드는 코드 결함**이라 이번에 고쳤습니다.
3. KOS 사진을 베이스로 쓰는 것은 **기술적으로 됩니다**(배관이 이미 있습니다). 다만 이 문제의
   해법으로는 과녁이 어긋나 있고, 법적 무게는 이 프로젝트에서 **가장 무거운 층**입니다(3장).

## 1. 실측 — 얼마나 닮았나

`outputs/` 의 Before 21장에서 ArcFace(얼굴 인식) 임베딩을 뽑아 서로 다른 두 장을 짝지은
**153쌍**의 유사도를 쟀습니다. 표 이미지 = `teemo/out/face-similarity-0909.png`.

| 짝의 종류 | 쌍 수 | 평균 | 중앙 | 최대 | ≥0.45 | ≥0.60(같은 사람) |
|---|---:|---:|---:|---:|---:|---:|
| 전체 | 153 | 0.099 | 0.089 | 0.421 | 0 | **0** |
| **같은 나라·나이·성별을 고른 짝** | 11 | **0.218** | 0.185 | 0.421 | 0 | **0** |
| 그 외 짝 | 142 | 0.089 | 0.084 | 0.308 | 0 | **0** |

- **"같은 사람"으로 판정될 쌍은 0건입니다.** 즉 골격 수준에서 얼굴이 복제되고 있지는 않습니다.
- 다만 같은 조건을 고른 짝은 평균이 **2.4배** 높습니다. 쌍둥이가 아니라 **사촌** 정도로 닮았습니다.

⚠ **한계 두 가지를 접지 않고 적습니다.**
- **표본이 작습니다** — 지금까지 만든 Before 가 21장뿐이고 그중 3장은 얼굴이 프레임 밖(볼만 크게
  찍힌 컷)이라 잴 수 없었습니다. 같은 조건 버킷은 **11쌍**이라 평균 0.218 은 흔들릴 수 있습니다.
- **이 숫자는 골격만 잽니다** — 머리 모양·화장·표정·색감이 겹쳐서 생기는 "비슷해 보임"은
  ArcFace 가 재는 축이 아닙니다. 성연서님이 화면에서 느끼신 건 이쪽일 가능성이 큽니다(2-3).

## 2. 원인 — 세 층으로 갈립니다

### 2-1. (1순위·확정) 인물 명단이 배치마다 반복됐다 — **고쳤습니다**

가장 닮은 두 쌍이 이걸 그대로 보여줍니다.

| 유사도 | 짝 | 인물 축 11개 중 다른 축 |
|---:|---|---|
| 0.421 | `09-09 10:01 / 0000` vs `09-09 10:29 / 0000` (china/30s/female) | **0개** |
| 0.392 | `09-09 10:01 / 0002` vs `09-09 10:29 / 0002` (korea/50s/male) | **0개** |

두 배치 모두 `nasolabial` 이고, 러너 `tools/run-selfie-batches.ps1` 의 기본값이 `-Seed 5` 였습니다.
`plan_batch` 는 seed 에 대해 결정적(deterministic)이라 **같은 시술 + 같은 seed = 같은 명단 8명**입니다.
실제로 재현됩니다:

```
같은 seed·같은 시술 두 번 → 명단 동일: True
```

게다가 중복 금지(`seen`)가 **배치 안에서만** 걸려 있어서, 다음 배치가 지난 배치의 사람을
다시 뽑는 것을 막는 장치가 아예 없었습니다.

전체 21장 중 **고유 인물 조합은 16개**였습니다 — 5장이 재탕입니다(24%).

**고친 것**
- `planner.py` — `signature()` / `past_signatures()` / `remember()` 신설.
  과거 배치가 쓴 인물 조합을 `outputs/person_registry.jsonl` 에 남기고 다음 배치가 그걸 피합니다.
  조합이 말라 요청 장수를 못 채우면 **배치가 조용히 줄지 않게** 배치 안 중복 금지만 남기고 채웁니다(fail-open).
- `batch.py` — 계획할 때 `avoid_sigs=past_signatures()`, 확정 후 `remember(plans, batch_id)`.
- `run-selfie-batches.ps1` — 기본 seed `5` → **`0`(회차마다 새로 뽑고 로그에 기록)**.
  재현이 필요하면 `-Seed <n>` 을 명시합니다.
- 회귀 `selftest.py` ⑳ 6종. **고치기 전 코드에서 실제로 실패하는지 확인했습니다**(3종 전부 실패).

### 2-2. (2순위·구조적) 글로 쓴 축은 얼굴을 다 못 가른다

인물 축 11개(나라·나이·성별·얼굴형·피부톤·피부상태·체형·머리·머리색·눈·기타)의 조합 수는
수백만이라 **조합이 모자란 게 아닙니다.** 문제는 `oval face, fair skin, monolid eyes` 같은
거친 말이 **얼굴 골격을 지정하지 못한다**는 것입니다. 그림 모델은 지정되지 않은 자리를
자기 평균 얼굴로 채웁니다 — 그래서 조건이 같으면 같은 쪽으로 수렴합니다(위 2.4배).

비유하면, 몽타주를 "계란형 얼굴에 밝은 피부"로만 설명하고 화가에게 맡기는 것과 같습니다.
말을 더 정교하게 해도 한계가 있고, 정확히 이 자리에서 **얼굴 씨앗 사진**이 효과가 큽니다(3장).

### 2-3. (3순위) 인상 축이 겹친다 — 골격보다 눈에 먼저 띈다

21장 중 **머리 모양이 `short` 인 것이 다수**였고, 배치가 작을수록 균형 샘플링이 한쪽으로 쏠립니다.
사람 눈은 골격보다 **머리·화장·표정·색감**을 먼저 봅니다. 즉 ArcFace 가 "다른 사람"이라고 해도
화면에서는 비슷해 보일 수 있습니다. 배치를 키우면 완화되지만, 별도로 재는 축이 필요합니다.

## 3. KOS 고객 사진을 베이스로 — 층별 판정

### 3-1. 기술 — **됩니다. 배관은 이미 있습니다**

- `providers/base.py` 의 `generate(prompt, aspect, ref=..., style_refs=...)` 에 **인물 참조 슬롯이
  이미 있고**, OpenAI 프로바이더는 참조가 있으면 `/images/edits` 로 보냅니다.
- 지금 Before 생성은 `ref=None` 입니다(`batch.py` ①). **여기에 씨앗 얼굴을 넣는 것이 전부**입니다.
- 사진도 있습니다 — 0907 실측: 체험단 표지 171명 중 **154명 보유·2,076장**(`bna/kos/FINDINGS-0907.md`).

### 3-2. 권리 — **지금은 못 씁니다. 0907의 사람 결정 3건이 그대로 미해결입니다**

`bna/kos/FINDINGS-0907.md` 마지막 절 그대로입니다.

1. 체험단 계약서·동의서에 **활용(AI 합성·변형 포함) 동의**가 있는가 — 확인 안 됨
2. 후보 171명 명단 검수(메모 매칭이라 무관한 건이 섞임) — 안 됨
3. EXIF 확인용 1장 열람 승인 — 안 됨

그리고 **파일명이 그대로 실명**(`실명_촬영일_UUID.jpg`, 표본 4,403개 전량)입니다.

⚠ **되돌릴 수 없는 지점**: 씨앗 사진은 GPT/Gemini 로 **업로드**됩니다. 한 번 올라가면 회수가 안 됩니다.
그리고 결과물은 "존재하지 않는 사람"이 아니라 **"실존 인물의 얼굴로 만든, 실제로는 일어나지 않은
시술 결과"** 가 됩니다 — 이 프로젝트에서 법적 무게가 가장 무거운 물건입니다(0907 문서 5-3).

### 3-3. 설계 — **이 문제의 해법으로는 과녁이 어긋나 있습니다**

| | KOS 실사진 씨앗 | 가상 얼굴 씨앗 은행 |
|---|---|---|
| 얼굴 다양성 | 큼 (실제 사람만큼) | 큼 (측정된 대로 서로 다름 — 1장 참조) |
| 씨앗 수 상한 | **154명** (그마저 동의 확인 후 줄어듦) | 무제한, 한 번 만들면 재사용 |
| 권리 | 최상위 문턱 · 사람 결정 3건 대기 | **0** |
| 비용 | 0 (사진은 이미 있음) | 씨앗 1장당 생성비 1회, 이후 무료 |
| 착수 가능 시점 | 법무·계약 확인 후 | **오늘** |

**핵심**: 이번 실측이 보여준 것은 "AI가 못 만들어서 얼굴이 겹친다"가 아니라 **"같은 명단을 다시
그렸다"** 입니다(2-1). 그리고 서로 다른 조합에서 나온 18개 얼굴은 **최대 0.421 로 전부 남남**이었습니다
— 즉 **가상 씨앗으로도 서로 다른 얼굴이 충분히 나옵니다.**

## 4. 권고 — 순서대로

| 순서 | 무엇 | 누가 | 비용 | 상태 |

| ① | seed 고정 해제 + 배치 간 인물 중복 금지 | 티모 | 0 | **완료(오늘)** |
| ② | **가상 얼굴 씨앗 은행** — 얼굴 N개를 1회 생성 → ArcFace 로 서로 안 닮은 것만 남김(기존 `dedup.Registry`, 문턱 0.75 재사용) → Before 의 `ref` 로 주입 | 티모 | 씨앗 1장당 생성 1회 | 지시 주시면 착수 |

| ④ | KOS 사진을 **스타일 참조**(피부 질감·조명, 얼굴 부위 제외)로 — 얼굴이 결과물에 안 남는 층이라 문턱이 가장 낮고, `samples_index.yaml` 의 `refs` 가 **지금 비어 있습니다** | 사람 결정 후 티모 | 0 | 동의 확인 대기 |

**②를 먼저 권합니다.** 다양성 이득은 ⑤와 사실상 같고, 권리 리스크는 0이며, 오늘 시작할 수 있습니다.
씨앗을 한 번 만들어 두면 그 다음부터는 "다양한 인물"이 생성 회차마다 새로 뽑는 운이 아니라
**은행에서 꺼내 쓰는 확정값**이 됩니다.
