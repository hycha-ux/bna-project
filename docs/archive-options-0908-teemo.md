# 원본 보관 자리 검토 — 구글드라이브 · 노션 (2026-09-08, 티모)

성연서님 물음: *"로컬에 있는 게 문제라면 구글드라이브나 노션에 아카이브하는 방법도 있다"*.

## 결론 먼저

**두 개의 다른 문제가 한 문장에 섞여 있었다.**

| 문제 | 원인 | 해법 | 상태 |
|---|---|---|---|
| ① 화면에 늦게 뜬다 | 내보내기가 10분 주기 하나뿐 | 생성 완료 시점 즉시 업로드 훅 | **오늘 해결**(`src/bna/cloudpush.py`) |
| ② 사진이 한 곳에만 있다 | `outputs/` 는 git 제외·백업 없음 | 별도 보관소로 야간 동기화 | **미해결 — 권고: 구글드라이브** |

**저장소를 드라이브·노션으로 바꿔도 ①은 안 빨라진다.** 어느 쪽이든 *이 PC가 올려야* 하고,
화면이 보는 곳은 여전히 Vercel Blob 이다. 즉 지연을 정하는 건 저장소 종류가 아니라 **올리는 시점**이고,
그건 오늘 훅으로 없앴다. 드라이브·노션의 가치는 ②(사본이 한 벌뿐인 문제)에 있다.

## 실측

- 생성 이미지 평균 **182KB**(6장·1,092KB 실측, gpt-image-2 셀카 기준).
  → 1,000장 ≈ 180MB · 10,000장 ≈ 1.8GB. **용량은 어느 선택지에서도 병목이 아니다.**
- 현재 사본은 사실상 **한 벌뿐**이다. Vercel Blob 에도 사진이 있지만 화면이 안 부르는 사진은
  `prune` 이 지우므로(설계된 동작) **백업이 아니다** — 배치를 지우면 같이 사라진다.
- 자동화 자격증명 없음: `teemo/keys.env` 에 구글·노션 키 없고, `rclone`·`gcloud` 도 이 PC에 없다.
- 대화 세션의 커넥터로는 구글드라이브·노션 **둘 다 접근된다**(hy.cha 계정으로 실확인).
  단 그건 사람이 붙어 있는 대화에서만 쓰는 통로다 — **예약작업(무인)에서는 못 쓴다.**

## 선택지

**A. 구글드라이브 — 권고.** 폴더째 밀어 넣으면 되고, 용량·복구·공유 범위 조절이 쉽다.
필요한 것은 **B&A 전용 서비스 계정 1개 + 그 계정에 공유한 폴더 1개**(파트장 콘솔 클릭 몇 번).
동기화는 **신규분만 올리고 지우지 않는 단방향**으로 짠다 — 이쪽에서 잘못 지워도 백업은 살아 있어야 한다.

**B. 노션 — 사진 보관용으로는 부적합.** 노션은 문서 안 첨부가 본체라 수천 장을 넣으면
찾기·되살리기가 어렵고, 폴더째 복구라는 개념이 없다. 대신 **"선택된 사진의 카탈로그"**
(시술·조건·통과 사유·대표 이미지 링크)로는 잘 맞는다 — 사람이 읽는 자리다.

**C. 지금처럼 두기.** PC 고장 = 생성물 전량 소실. 지금까지 만든 양이 적어 손실이 작을 뿐,
장수가 쌓일수록 위험은 커진다.

## 권고 순서

1. (완료) 즉시 업로드 훅 — 화면 지연 제거.
2. 구글드라이브 야간 백업 1회/일. 착수 조건 = **B&A 전용 서비스 계정 키**(팀 기존 키 재사용 금지).
3. 노션 카탈로그는 "쓴다(라이브러리)" 단계가 자리 잡은 뒤 검토.

⚠ 참조 사진(`samples/reference/`)에 실제 인물이 섞여 있으면 드라이브 폴더 공유 범위를
**서비스 계정 + 지정 인원**으로 제한한다. 생성물은 합성이지만 참조는 사람일 수 있다.
