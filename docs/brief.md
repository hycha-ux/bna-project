# 프로젝트 브리프 — 온리프 B&A 자동 생성기

작성일: 2026-09-07 · 담당: 메디빌더 디자인 · 저장소: hycha-ux/bna-project

## 한 줄 정의
시술과 모드만 고르면 **프롬프트가 자동으로 써지고, Before/After 이미지 쌍이 바로 출력되어, 검수까지 통과한 것만 갤러리에 쌓이는** 도구.

## 왜 만드나
- 온리프 광고·후기 콘텐츠에 시술별 B&A 이미지가 지속적으로 필요하지만, 실제 임상 사진은 수급·동의·품질 편차 문제가 큼.
- 2026년 초 만든 **prompf(브랜드 프롬프트 대시보드)**로 "프롬프트 자동 조합"은 검증됐음. 그러나 결과물이 텍스트였고, 사람이 외부 툴에 붙여넣고 골라내는 수작업이 남아 있었음.
- 이번엔 그 다음 단계: **프롬프트 → 이미지 → 검수 → 저장**을 한 흐름으로 닫는다.

## 전작(prompf)에서 가져오는 것

| 자산 | 상태 | 이번 프로젝트에서 |
|---|---|---|
| 브랜드 DB (온리프 컬러·톤·금지어) | 완성 | 그대로 재사용. 브랜드 톤 레이어로 편입 |
| 허용 풀 + 금지 목록 (정석/변주 모드) | 완성 | **모드별 제약(mode_rules)** 로 계승. 임상 모드 = 정석, 셀카 모드 = 변주 |
| 레이어형 프롬프트 조합 공식 | 완성 | 구조 유지, 레이어 내용은 교체 (아래 "강화" 참고) |
| 스텝 위저드 + 칩 선택 UI (IBM Carbon) | 프로토타입 | UI 골격 재사용. 마지막 스텝을 "복사"에서 "생성"으로 교체 |
| 카테고리 시술전/후/비교 | 이름만 존재 | 실제 로직으로 구현하는 게 이번 프로젝트의 본체 |

## 전작 대비 강화 포인트 (핵심)

### 1. "예쁜 화보"에서 "진짜 사진"으로 방향 전환
prompf의 고정 스타일은 `soft feminine clean studio beauty portrait, 8K, hyperrealistic` 계열. 광고 화보엔 맞지만 **B&A에서는 오히려 AI 티의 원인**.
→ 리얼리티 레이어를 새로 설계: 실제 폰 카메라 특성(화소·노이즈·기본 색보정), 불완전한 조명(역광·형광등), 피부 결(모공·솜털·잡티) **유지**를 명시. 뷰티 리터칭 금지.

### 2. 전후 쌍 일관성: 두 번 그리지 않고 한 번 그리고 편집
prompf는 before/after 카테고리가 분리되어 있어 같은 사람이 나올 보장이 없었음.
→ **Before 생성 → Before 이미지를 입력으로 시술 부위만 편집 → After.** 인물·구도·조명·배경이 구조적으로 동일해짐.

### 3. 시술별 변화 스펙을 데이터로 관리
"시술 후"라는 한 단어 대신, 시술마다 부위·변화 방향·강도 상한을 정의 (`config/treatments.yaml`). 과장 금지가 룰에 박힘.

### 4. 변주 축의 목적 전환
prompf 변주 = 브랜드 무드 안에서의 다양성 (포즈·헤어·의상).
B&A 변주 = **후기의 진짜스러움을 위한 다양성** (나라·연령·성별·배경·각도·조명·색감·화소). 축 자체를 교체.

### 5. 자동 검수와 재생성 루프
prompf에는 결과를 판단하는 단계가 없었음.
→ 비전 모델이 7항목 체크리스트(손가락·피부·머리카락·동일성·부위 외 변화·효과 가시성·AI 티)를 채점. 미달 시 자동 재생성. **사람은 통과한 것만 본다.**

### 6. 결과가 데이터로 쌓임
모든 생성 건의 (변주 조합 → 프롬프트 → 이미지 → 점수)를 로그로 저장. 어떤 조합이 잘 나오는지 축적 → 프롬프트 개선과 향후 학습 코퍼스로 활용. (디자인 자동화 플랜 Track B와 같은 사상)

## 범위

**포함**
- 시술 8종 (팔자 1순위, 스킨부스터 엠보 2순위 → 나머지 순차)
- 모드 2종: 후기용(임상, 동일 구도) / 셀카용(일반인)
- 프롬프트 자동 조립, 이미지 생성·편집, 자동 검수, 갤러리, 히스토리
- 모델 3종 비교(GPT Image / Gemini / Higgsfield) 후 역할 확정

**제외 (이번 단계)**
- 실제 환자 사진 기반 편집 (동의·법무 이슈, 별도 트랙)
- 좌우 합성 카드 디자인 (기존 디자인 자동화 파이프라인이 담당)
- 타 브랜드 확장 (구조는 열어두되 온리프만)

## 성공 기준
- 팔자주름 셀카 모드에서 **검수 통과율 60% 이상**, 통과작 중 담당자 육안 합격 80% 이상
- 요청부터 통과작 4장 확보까지 5분 이내
- 디자이너 아닌 BX·그로스 팀원이 문서 없이 사용 가능

## 리스크
- **광고 심의**: 생성 이미지의 후기 사용은 표기 의무 등 확인 필요. 기획 단계에서 법무 확인.
- **모델 편차**: 리얼리티는 모델에 크게 의존. 키 수령 즉시 비교 스파이크로 조기 판단.
- **손가락·피부 실패율**: 셀카 모드 자체 통과율이 낮을 수 있음 → 손 없는 셀카 구도를 기본값으로 두고 손 포함은 옵션화.

## 팀·계정
- BX·그로스 계정: 메디빌더 구글계정 기준, 관리자급 권한
- API 키: GPT, Gemini, Higgsfield (사용자가 `.env`에 직접 입력)
