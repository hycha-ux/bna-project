# 설계 검토 — 목표 달성을 위해 더 필요한 것 (2026-09-07)

> **반영 상태 (같은 날):** A1~A7 전부 설계 문서·모듈 골격에 반영. A7은 "전부 오픈, 법무 가이드 추후"로 결정. B2·B5·B6·B1(훅)도 함께 반영. 남은 것: B3 AI 탐지기, B4 블라인드 테스트 도구, B7 유명인 유사도.

현재 설계는 프롬프트 조립·변주·플래너까지는 탄탄하지만, **세 축 모두 "프롬프트 문장"에 의존**하고 있다. 목표는 프롬프트가 아니라 **참조 이미지 · 수치 검증 · 마스크 · 피드백 루프**로 달성된다. 우선순위 순.

## A. 반드시 추가 (없으면 목표 미달)

### A1. 참조 이미지 기반 생성 (축 ① 실사)
- 문제: 텍스트만으로 "진짜 사진 같음"을 끌어내는 데 한계. 모델은 자기 학습분포의 "예쁜 사진"으로 회귀함.
- 추가: `samples/reference/{clinical,selfie}/` 실사 라이브러리를 만들고, 생성 시 **스타일 참조 이미지 1~2장을 함께 입력**. 프롬프트에 "이 사진과 같은 카메라·조명·피부 질감으로".
- 설계 변경: `Provider.generate(prompt, aspect, ref=..., style_refs=[...])`. 참조 라이브러리에 태그(모드·조명·화소)를 달아 변주 축과 매칭.

### A2. 후처리 "카메라 아티팩트" 레이어 (축 ①)
- 문제: 생성 직후 이미지는 너무 깨끗함(노이즈 없음, 완벽한 선명도, 압축 흔적 없음). 사람 눈이 AI라고 느끼는 마지막 5%.
- 추가: `postprocess.py` — 화소 축에 맞춘 센서 노이즈, JPEG 재압축(품질 70~90), 미세 색수차, 폰 HDR 톤 특성, 약한 렌즈 왜곡. 임상 모드는 노이즈 최소·중립. 결정적(seed 고정)으로 적용해 재현 가능.
- 주의: Before/After 세트에는 동일 파라미터 적용 (임상은 완전 동일, 셀카는 드리프트된 화소 축 반영).

### A3. 얼굴 임베딩 동일성 게이트 (동일 인물)
- 문제: 비전 LLM의 "같은 사람인가" 판단은 관대함. 수치 기준이 없음.
- 추가: `qa/identity.py` — ArcFace 계열(insightface) 임베딩 코사인 유사도. 임계값(초안 0.6)은 스파이크에서 실제 사진 쌍으로 캘리브레이션. 하드 페일 게이트. 3컷 시리즈에도 적용.

### A4. 랜드마크 기반 부위 마스크 편집 (축 ② 임상)
- 문제: "시술 부위만 바꿔라"를 문장으로 지시하면 모델이 얼굴 전체를 미세하게 다시 그림 → 동일 조건이 흐트러짐.
- 추가: `qa/landmarks.py`(MediaPipe)로 얼굴 랜드마크 추출 → 시술별 부위 폴리곤(`treatments.yaml`에 `mask_region` 추가: 팔자=코날개~입꼬리, 모공=볼, 리프팅=턱선…) → 마스크 생성 → **마스크 편집 지원 모델에서는 마스크 밖 픽셀을 원본으로 강제 복원**. 지원 안 하는 모델도 생성 후 마스크 밖을 원본으로 합성(compositing)하면 동일 조건이 픽셀 단위로 보장됨.
- 이 한 가지가 축 ②를 "프롬프트 희망"에서 "구조적 보장"으로 바꿈.

### A5. 정렬·프레이밍 구조 검사 구현 (축 ②)
- 설계에는 있으나 구현 계획이 없음. A4의 랜드마크를 재사용해 눈 중심 거리 대비 위치 오차, 얼굴 크기 비율, 밝기 차이를 계산. 임계값은 `clinical_rig.yaml`에 이미 정의.

### A6. 검수 결과 → 프롬프트 개선 피드백 루프 (축 ③ 대량생산)
- 문제: 통과율을 "측정"만 하고 "올리는" 장치가 없음. 대량생산은 통과율이 곧 처리량·비용.
- 추가:
  1. 모든 item 메타에 **프롬프트 버전(git hash + config hash)** 기록
  2. `stats.py` — 축별·프롬프트 버전별 통과율, 실패 사유 분포(어느 검수 항목에서 떨어지는지)
  3. **A/B 실험 모드**: 같은 변주 세트에 프롬프트 두 버전을 돌려 통과율 비교
  4. 사람 리뷰 UI에서 불합격 사유 태그(손·피부·동일성·AI티…) → 통계에 합산
- 이게 있어야 "어떤 조합·문구가 잘 뽑히는지"가 쌓이고, 변주 가중치와 프롬프트를 데이터로 조정할 수 있음.

### A7. 광고 심의·법무 정책 확정 (프로젝트 리스크)
- 문제: 의료광고에서 치료 전후 사진은 의료법상 제한·심의 대상. 생성 이미지를 "실제 후기"로 제시하면 문제 소지가 큼.
- 추가: 사용 범위 정책 문서(내부 참고용 / 일러스트 표기 후 사용 / 광고 심의 제출 등 단계별), 생성 이미지 표기 규칙, 파일에 **보이지 않는 워터마크 또는 메타데이터 표식**(출처 추적용). 설계 착수 전 법무 확인 필요. 이건 코드가 아니라 결정 사항.

## B. 권장 (품질·효율을 크게 올림)

- **B1. 모델별 프롬프트 어댑터**: 프롬프트 방언이 모델마다 다름(GPT는 서술형, 일부 모델은 키워드+negative). `providers/{model}/adapter.py`에서 공통 스펙을 모델별 문장으로 변환.
- **B2. 시술 효과 강도·경과 시점 축**: 효과 강도(subtle/moderate)와 시점(직후·1주·4주)을 축으로. 셀카 모드에서 "시술 1주 후 미세 홍조 잔존" 같은 디테일이 리얼리티를 올림. `after_change`는 의료진 검수 필요(과장·오류 방지).
- **B3. AI 탐지기 점수**: 오픈소스 AI 이미지 분류기를 검수 항목에 추가. 비전 LLM과 다른 관점의 신호.
- **B4. 블라인드 테스트 도구**: 브리프의 "구분율 60% 이하" 지표를 실제로 잴 도구. 실제/생성 섞어 팀원에게 보여주고 응답 기록. 간단한 웹 페이지면 충분.
- **B5. 배치 간 전역 중복 검사**: 지금은 배치 내 중복만. 얼굴 임베딩 레지스트리로 과거 배치와도 비교.
- **B6. 프로바이더 단가표·처리량 계측**: `pricing.yaml` + 호출당 시간·비용 로깅. "통과작 1장당 평균 비용"이 예산의 기준.
- **B7. 유명인 유사도 방지**: 생성 얼굴이 실존 유명인과 닮는 사고 방지. 프롬프트 금지어 + 필요시 유명인 임베딩 대조.

## C. 나중 (운영 단계)

- Supabase 저장·권한, 슬랙 알림 (기존 로드맵 4단계)
- 리뷰 UI (통과작 갤러리 + 사유 태그) — A6과 함께 설계
- 3컷 시리즈 자동 생성 (모델의 다각도 일관성 확인 후)
- 타 브랜드 확장 (브랜드 리그·시술 정의만 추가하면 되도록 구조 유지)
